═══════════════════════════════════════════
错误日志级别说明
═══════════════════════════════════════════

1. info - 信息性消息
2. warning - 警告，可能需要关注
3. error - 错误，影响功能但系统可继续运行
4. critical - 严重错误，可能导致系统崩溃

═══════════════════════════════════════════
错误日志类型说明
═══════════════════════════════════════════

1. error - 一般错误
2. security - 安全相关错误（登录、注册、权限等）
3. performance - 性能问题
4. system - 系统级错误（数据库、服务器等）

═══════════════════════════════════════════
如何查看错误日志
═══════════════════════════════════════════

方法 1: 后台管理界面
---------------------
1. 登录系统
2. 进入后台管理 → 系统监控
3. 查看"错误日志统计"表格
4. 显示最近的错误日志（按时间倒序）

方法 2: 数据库查询
---------------------
-- 查看所有错误日志
SELECT * FROM system_logs 
ORDER BY created_at DESC 
LIMIT 50;

-- 按级别统计
SELECT log_level, COUNT(*) as count
FROM system_logs
GROUP BY log_level;

-- 查看最近24小时的错误
SELECT * FROM system_logs
WHERE created_at >= NOW() - INTERVAL '24 hours'
  AND log_level IN ('error', 'critical')
ORDER BY created_at DESC;

-- 查看特定类型的错误
SELECT * FROM system_logs
WHERE log_type = 'security'
ORDER BY created_at DESC;

═══════════════════════════════════════════
如何添加新的错误日志记录
═══════════════════════════════════════════

步骤 1: 导入函数
-----------------
const { logSystemLog } = require("../services/activityService");

步骤 2: 在 catch 块中调用
--------------------------
try {
  // 可能出错的代码
} catch (error) {
  // 记录错误日志
  logSystemLog(
    'error',           // 级别: info, warning, error, critical
    'error',           // 类型: error, security, performance, system
    `操作失败: ${error.message}`,  // 消息
    {                  // 详细信息（可选）
      stack: error.stack,
      code: error.code,
      customData: "..."
    },
    req.user?.id,      // 用户ID（可选）
    req                // 请求对象（可选，用于获取IP和User-Agent）
  ).catch(err => console.error("记录错误日志失败:", err));
  
  // 继续错误处理...
}

步骤 3: 选择合适的级别和类型
-----------------------------
- 数据库错误 → critical/system
- 认证错误 → error/security
- 业务逻辑错误 → error/error
- 性能问题 → warning/performance

═══════════════════════════════════════════
数据库表结构
═══════════════════════════════════════════

system_logs 表字段:
- id: 主键
- log_level: 日志级别 (info/warning/error/critical)
- log_type: 日志类型 (error/security/performance/system)
- message: 错误消息
- details: 详细信息 (JSONB)
- user_id: 用户ID（外键，可选）
- ip_address: IP地址（可选）
- user_agent: 浏览器信息（可选）
- created_at: 创建时间

索引:
- idx_system_logs_level (log_level)
- idx_system_logs_type (log_type)
- idx_system_logs_created_at (created_at DESC)
- idx_system_logs_level_type (log_level, log_type, created_at DESC)

═══════════════════════════════════════════
注意事项
═══════════════════════════════════════════

⚠️ 1. 不要在循环中频繁记录日志
   - 可能导致性能问题
   - 可能导致数据库表快速增长

⚠️ 2. 敏感信息保护
   - 不要在日志中记录密码
   - 注意用户隐私信息
   - 建议在 details 中只记录必要信息

⚠️ 3. 日志清理
   - 定期清理旧日志（建议保留30-90天）
   - 可以设置定时任务自动清理

⚠️ 4. 错误日志本身失败
   - 所有 logSystemLog 调用都用 .catch() 处理
   - 避免记录错误日志本身导致系统崩溃

═══════════════════════════════════════════
维护建议
═══════════════════════════════════════════

1. 定期查看错误日志

2. 设置告警
   - 当 critical 错误出现时发送通知
   - 当某类错误频繁出现时告警

3. 数据库维护
   -- 清理30天前的日志
   DELETE FROM system_logs 
   WHERE created_at < NOW() - INTERVAL '30 days';
