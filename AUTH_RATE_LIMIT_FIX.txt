===========================================
认证和速率限制问题修复总结
===========================================

问题描述：
-----------
用户反馈在正常使用过程中（多次进入和退出文档），系统会频繁要求重新登录，
并提示"登录次数太多，请稍后重试"的错误信息。

问题分析：
-----------
1. JWT token 过期时间过短（默认 1 小时），导致用户在使用过程中频繁过期
2. 认证速率限制设置过于严格（15分钟内仅允许 20 次认证请求）
3. 前端缺少响应拦截器处理 401 错误，导致 token 过期时未及时清理和重定向
4. 当 token 过期但用户未察觉时，继续操作会触发多次认证请求，达到速率限制

修复方案：
-----------

【修复 1】增加 JWT Token 过期时间
  文件: backend/config/env.js
  修改: 将 JWT_EXPIRES_IN 从 "1h" 增加到 "24h"
  效果: 用户可以在 24 小时内持续使用，无需重新登录

【修复 2】放宽认证速率限制
  文件: backend/config/env.js
  修改: 将 AUTH_RATE_LIMIT_MAX 从 20 增加到 50
  效果: 15 分钟内允许 50 次认证请求，避免正常使用被限制

【修复 3】更新速率限制器注释
  文件: backend/middleware/rateLimiter.js
  修改: 更新 authLimiter 的注释说明
  效果: 代码注释与实际配置保持一致

【修复 4】添加前端响应拦截器
  文件: frontend/src/api.js
  新增: axios 响应拦截器，处理 401 错误
  效果:
    - 自动检测 token 过期（401 错误）
    - 清除失效的 token
    - 自动重定向到登录页
    - 避免多次重复请求导致速率限制

技术细节：
-----------
1. 速率限制器配置了 skipSuccessfulRequests: true
   这意味着只有失败的认证请求才会被计入限制
   
2. 响应拦截器增加了路径检查和延迟跳转
   避免在登录/注册页面时重复重定向

3. JWT token 过期时间可以通过环境变量 JWT_EXPIRES_IN 自定义

测试建议：
-----------
1. 测试正常登录后可以持续使用 24 小时而不需要重新登录
2. 测试多次进出文档不会触发速率限制
3. 测试 token 过期后会自动跳转到登录页
4. 测试在 15 分钟内多次登录失败（密码错误）会触发速率限制

环境变量配置（可选）：
-----------
如需自定义配置，可在 backend/.env 文件中添加：

# JWT token 过期时间（默认 24h）
JWT_EXPIRES_IN=24h

# 认证速率限制 - 时间窗口（毫秒，默认 15 分钟）
AUTH_RATE_LIMIT_WINDOW_MS=900000

# 认证速率限制 - 最大次数（默认 50）
AUTH_RATE_LIMIT_MAX=50
