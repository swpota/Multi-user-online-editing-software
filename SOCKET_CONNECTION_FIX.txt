===========================================
Socket 连接频繁重连问题修复
===========================================

问题描述：
-----------
用户反馈每次进入文档时，后端日志显示大量的 Socket 连接和断开事件。
进出文档 5 次后，产生了数十次的连接/断开日志，最终触发速率限制，
导致用户无法登录（显示"登录请求过于频繁，请稍后再试（建议等待 14 分钟）"）。

问题根源：
-----------
EditorPage 组件中的 Socket 连接 useEffect 的依赖项设置不当：

```javascript
useEffect(() => {
  const s = io("http://localhost:5000");
  setSocket(s);
  
  fetchDocument();
  fetchComments();
  fetchTasks();
  
  // ... 设置监听器 ...
  
  return () => {
    s.disconnect();
  };
}, [documentId, user, fetchDocument, fetchComments, fetchTasks, featureSettings]);
//  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//  问题：这些依赖项频繁变化，导致 useEffect 不断重新执行
```

依赖项问题：
1. `fetchDocument`、`fetchComments`、`fetchTasks` 是 useCallback 函数
   - 它们的引用可能在每次渲染时变化
   - 导致 useEffect 频繁重新执行

2. `featureSettings` 是对象
   - 对象引用可能在每次渲染时创建新实例
   - 导致 useEffect 频繁重新执行

3. 每次 useEffect 重新执行时：
   - 创建新的 Socket 连接
   - 断开旧的 Socket 连接
   - 重新加载文档数据
   - 导致：连接 → 断开 → 连接 → 断开 的无限循环

修复方案：
-----------

【修复 1】移除函数依赖
  - 不再依赖 `fetchDocument`、`fetchComments`、`fetchTasks` 函数
  - 在 useEffect 内部直接调用 API 加载数据
  - 避免函数引用变化导致的重新执行

【修复 2】优化对象依赖
  - 不再依赖整个 `featureSettings` 对象
  - 只依赖具体的属性：
    - `featureSettings.enable_comments`
    - `featureSettings.enable_tasks`
  - 避免对象引用变化导致的重新执行

【修复 3】优化用户依赖
  - 将 `user` 改为 `user?.id`
  - 只有用户 ID 变化时才重新连接
  - 避免 user 对象其他属性变化导致重连

【修复 4】添加调试日志
  - 添加连接和断开的 console.log
  - 方便监控 Socket 连接状态
  - 及时发现异常的重连行为

修复后的代码：
-----------

```javascript
useEffect(() => {
  if (!user) return;

  console.log("建立 Socket 连接 - documentId:", documentId);
  const s = io("http://localhost:5000");
  setSocket(s);

  // 直接在这里加载数据，避免依赖外部函数
  const loadData = async () => {
    try {
      // 加载文档
      const response = await api.get(`/documents/${documentId}`);
      // ... 处理文档数据 ...

      // 加载评论（如果启用）
      if (featureSettings.enable_comments) {
        const commentsResponse = await api.get(`/documents/${documentId}/comments`);
        setComments(commentsResponse.data || []);
      }

      // 加载任务（如果启用）
      if (featureSettings.enable_tasks) {
        const tasksResponse = await api.get(`/documents/${documentId}/tasks`);
        setTasks(tasksResponse.data || []);
      }
    } catch (error) {
      console.error("加载数据失败", error);
    }
  };

  loadData();
  s.emit("joinDocument", { documentId, user });

  // ... 设置事件监听器 ...

  return () => {
    // ... 移除事件监听器 ...
    s.disconnect();
    console.log("断开 Socket 连接 - documentId:", documentId);
  };
}, [documentId, user?.id, featureSettings.enable_comments, featureSettings.enable_tasks]);
// ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
// 修复后：只依赖真正变化的值
```

修复效果：
-----------
✅ Socket 连接只在以下情况下重新建立：
  - documentId 变化（切换到其他文档）
  - user?.id 变化（切换用户）
  - 评论/任务功能开关变化（极少发生）

✅ 正常情况下：
  - 进入文档：建立 1 次连接
  - 退出文档：断开 1 次连接
  - 不再出现频繁的连接-断开循环

✅ 避免触发速率限制：
  - 大幅减少请求次数
  - 用户可以正常进出文档
  - 不会再因为"请求过于频繁"而被限制登录

测试建议：
-----------
1. 清除浏览器缓存和 localStorage
2. 重新登录
3. 进入文档，观察后端日志：
   - 应该只看到 1 次 "一个客户端已连接"
   - 应该只看到 1 次 "用户 XXX 加入了文档房间"
4. 退出文档，观察后端日志：
   - 应该只看到 1 次 "客户端已断开连接"
5. 多次进出文档（10-20 次），确认：
   - 每次只有 1 对 连接/断开 日志
   - 不会再触发速率限制
   - 可以正常使用

注意事项：
-----------
- 如果仍然看到多次连接，检查是否有其他组件也在创建 Socket 连接
- 确保后端速率限制配置已更新（AUTH_RATE_LIMIT_MAX=50）
- 确保 JWT token 过期时间已增加（JWT_EXPIRES_IN=24h）
