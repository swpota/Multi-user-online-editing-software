问题 1: 系统设置更新日志过多
═══════════════════════════════════════════

【问题】
更新一次系统设置，后端显示16条 UPDATE_SYSTEM_SETTING 日志。

【原因】
每个设置项更新都记录一条日志，导致日志爆炸。

【修复】
✅ 合并为一条日志
- 文件：backend/routes/adminRoutes.js
- 修改：将 for 循环中的每次记录改为循环结束后记录一次
- 日志类型：UPDATE_SYSTEM_SETTINGS（复数）
- 包含信息：所有变更的设置和变更数量

【效果】
更新16个设置：
❌ 修复前：16条日志
✅ 修复后：1条日志（包含所有变更详情）

问题 3: 用户分析功能未实现
═══════════════════════════════════════════

【问题】
用户分析页面所有统计数据都是 0，虽然用户创建了很多文档。

【诊断】
这是一个**半成品功能**：
✅ 前端展示页面完整
✅ 后端 API 完整
✅ 数据库表已创建
❌ 关键的数据记录功能缺失

只有登录和注册被记录，其他操作都没有记录到数据库。

【修复】
已完成5个核心功能的活动记录：

✅ 1. 文档创建统计
   - 文件：backend/routes/documentRoutes.js
   - 位置：POST "/" 路由
   - 活动类型：document_create
   - 记录信息：文档ID、标题、分类

✅ 2. 文档编辑统计
   - 文件：backend/routes/documentRoutes.js
   - 位置：PUT "/:id" 路由
   - 活动类型：document_edit
   - 记录信息：文档ID、标题

✅ 3. 评论创建统计
   - 文件：backend/routes/commentRoutes.js
   - 位置：POST "/documents/:documentId/comments" 路由
   - 活动类型：comment_create
   - 记录信息：评论ID、文档ID、父评论ID

✅ 4. 任务创建统计
   - 文件：backend/routes/taskRoutes.js
   - 位置：POST "/documents/:documentId/tasks" 路由
   - 活动类型：task_create
   - 记录信息：任务ID、文档ID、分配对象

✅ 5. 任务完成统计
   - 文件：backend/routes/taskRoutes.js
   - 位置：PUT "/tasks/:taskId" 路由
   - 活动类型：task_complete
   - 触发条件：状态从非完成变为完成
   - 记录信息：任务ID、文档ID、之前状态

【效果】
重启后端后，所有新的操作都会被记录：
- 创建文档 → document_create +1
- 编辑文档 → document_edit +1
- 创建评论 → comment_create +1
- 创建任务 → task_create +1
- 完成任务 → task_complete +1

【注意】
⚠️ 历史数据不会被统计
- 之前创建的文档不会出现在统计中
- 只有修复后的新操作才会被记录
- 这是正常的，因为之前没有记录机制

数据库表结构
═══════════════════════════════════════════

user_activities 表：
- id: SERIAL PRIMARY KEY
- user_id: INTEGER (外键到 users)
- activity_type: VARCHAR(50) (活动类型)
- resource_type: VARCHAR(50) (资源类型)
- resource_id: INTEGER (资源ID)
- details: JSONB (额外信息)
- ip_address: VARCHAR(45) (IP地址)
- user_agent: TEXT (浏览器信息)
- created_at: TIMESTAMPTZ (创建时间)

支持的 activity_type：
- register: 注册
- login: 登录
- document_create: 创建文档
- document_edit: 编辑文档
- document_view: 查看文档（未实现）
- comment_create: 创建评论
- task_create: 创建任务
- task_complete: 完成任务
- task_update: 更新任务（已记录）
